## 1. RFID基础原理介绍

在开始破解之前，了解一下基础知识会很有帮助。如果你只想了解知道怎么破解，请跳转至第二部分，如果你不想要动脑什么都不想学习，可以跳转至第三部分。

### 1.1  IC卡( Mifare Classic )数据结构

一块Mifare Classic卡有**16个扇区(sector)**，每个扇区有**4个块(block)**

```
MIFARE Classic 卡片
├── 扇区 0 (Sector 0)
│   ├── 块 0 (Block 0) - 制造商信息
│   ├── 块 1 (Block 1) - 用户数据
│   ├── 块 2 (Block 2) - 用户数据
│   └── 块 3 (Block 3) - 密钥A + 访问控制 + 密钥B
├── 扇区 1 (Sector 1)
│   ├── 块 0 - 用户数据
│   ├── 块 1 - 用户数据
│   ├── 块 2 - 用户数据
│   └── 块 3 - 密钥A + 访问控制 + 密钥B
└── ... 共 16 个扇区
```

其中，**0扇区(sector 0)**的**块0(block 0)**是一行特殊的认证数据，包含了卡片的**UID**，**参数**等数据。大概长成这样

```
1234ABCD66F08040004D85E8C5342D290
```

这是一串我瞎编的数据，帮助你了解数据的内容：

+ 第0-3字节（即第0-7个数字，此处的`1234ABCD`）：**UID**，这是门禁系统的主要认证凭证，通常而言复制了UID就可以打开一些最低级的门禁。
+ 第4字节（即第8-9个数字，此处的`66`）：**校验字节**，用前面的UID计算而得，由于我是瞎编的所以这个校验位是不正确的。
+ 第5-15字节（即第10-31个数字，此处的`F08040004D85E8C5342D290`）：**厂商数据**，包括芯片类型、生产批次等信息

然后，每个扇区的最后一个块记录了这个扇区对应的**密钥A**、**访问控制**、**密钥B**。大概长成这样

```
FFFFFFFFFFFFFF078069FFFFFFFFFFFF
```

这是默认的数据，传递的信息如下：

+ 第0-5字节（即第0-11个数字，此处的`FFFFFFFFFFFF`）：**密钥A**，一些加密的认证系统会验证密钥才能访问扇区内的数据，通常而言直接复制UID不能成功的卡片就是因为读卡器验证了加密扇区的数据
+ 第6-9字节（即第12-19个数字，此处的`FF078069`）：**访问控制位**，定义了扇区的访问权限，如读写加减等
+ 第10-15字节（即第20-31个数字，此处的`FFFFFFFFFFFF`）：**密钥B**，第二个密钥，功能同上

### 1.2  正常认证过程

以下的内容呈现了一次正常认证中，读卡器读取一个扇区数据的过程。

+ 读卡器 --(request)--> 卡片：读卡器检测到卡片，发出了认证认证申请，发送认证某一扇区的**请求**（一次只能认证一个扇区），并声明使用**密钥A还是密钥B**。
+ 卡片 --(Nt)-->读卡器 ：卡片回应，并发送一个随机数**挑战**（Nt），用来验证读卡器合法性。
+ 读卡器 --(Nr and Ar)--> 卡片：读卡器读取到卡片的挑战（Nt），随后根据自带的密钥计算**加密后**得到**回答**（Nr），随后读卡器也发起一个随机数**挑战**（Ar），用来验证卡片合法性。
+ 卡片 --(At)--> 读卡器：卡片得到来自读卡器的加密**回答**（Nr），自己也把刚才**自己发的随机数挑战**（Nt）用自己的密钥**加密**，然后比对两个加密数据进行**验证**，若相同则验证成功，读卡器合法。同时自己加密来自读卡器的**挑战**（Ar），发送对应的**回答**（At）。
+ 读卡器 --(access)--> 卡片：读卡器得到**回答**（At）后，自己也把刚才**自己发的随机数挑战**（Ar）用自己的密钥**加密**，然后比对两个加密数据进行**验证**，若相同则验证成功，卡片合法。双方互相验证成功，进行进一步访问。值得注意的是，之后所有的信息交流都是基于这个扇区密钥**加密**的！

## 2. 三种常见复制方式

说是复制，但是以下方法的目的都是获得密钥。不过获得了密钥就可以进行认证，读取卡片数据，也就可以复制到空白卡片上了。

### 2.1 字典攻击

这是最低级的破解方式，甚至用手机就可以做到。

**可复制卡片的条件**：需要完全没有加密！每个扇区的密码都是默认的`FFFFFFFFFFFF`，或者其他常见的默认密码，通过字典就可以试出密钥。

**原理**：手机的NFC功能或者软件`Mifare Classic Tool`就可以直接使用默认密码来模仿读卡器进行验证，直接穷举常见的默认密码，进行验证，验证成功后即可读取对应扇区的数据。

**优点**：只要你有手机，就是0成本，甚至直接把手机当做一个门禁（也就是常说的手机复制门禁）。

**缺点**：但凡有一点加密，且读卡器认证时验证了加密扇区内容，就无法读取并复制了。

### 2.2 嵌套攻击

当下最常见的半加密卡破解手段，不过需要一些专业的设备（如PN532, Proxmark3）。

**可复制卡片的条件**：有至少一个扇区可以使用**字典攻击**破解，并且是最传统的`Mifare Classic`卡片，没有进行**随机数改进**（这是什么，会在下一个攻击手段中介绍）

**原理**：

+ 使用一些专业设备假装读卡器，首先用字典攻击**获得一个扇区的访问权限**（假如是扇区0），**建立会话通讯通道**，接下来准备破解未知密钥的加密扇区（假如是扇区1）。
+ 攻击者先获得大量随机数挑战，获得大量随机数序列，由于卡片的**LFSR随机数算法**的特性——**线性且可递推**，从而反推出随机数生成（PRNG）的状态。攻击者可以**预测下一次随机数的明文**！
+ 设备不是直接请求扇区1，而是利用和扇区0建立的通讯通道调用扇区1进行认证（此处卡了一个Mifare Classic卡片固有的特性：可以借助某个已知扇区访问其他扇区。因为正常情况下，这确实在某些情况下需要用到）。按照先前讲到的验证逻辑，扇区1会发出一个**随机数挑战Nt**，但是由于卡片还在**会话状态**，所有的数据都会经过该扇区的加密，所以设备接收到的Nt是被扇区1**加密的**！现在，攻击者得到了这次挑战的**明文（由大量随机数预测）和密文（在会话中的挑战Nt）**。
+ 在这里先补充一下`Encrypto-1`的加密特性：`ciphertext = plaintext ⊕ keystream`（以防你不知道，圆圈加号是**异或**运算）。此处的keystream：由密钥生成初始值，循环生成的48bit序列，生成的算法也是**LFSR**。总之，如果你获得了**keystream**的状态（就这个攻击而言，可以获得32bit），可以大大减少初始key的枚举范围。
+ 攻击者通过明文和密文进行异或运算直接得到keystream的32bit序列，可以反推出可能的密钥。同时还可以利用奇偶校验位的特性，进一步缩小枚举范围（这已经结合了硬嵌套攻击）。
+ 攻击者重复上述步骤，仅需6-8次就可以把可能的密钥缩小在100以内，所以几秒钟就可以破解了。

**优点**：当下绝大多数的量产门禁卡都是半加密的，也就是说这一招可以破解绝大多数的卡片了，且几秒钟就可以破解。

**缺点**：你可能需要花点钱买专业设备，而且少数改进后的卡片免疫了这种攻击，他们的随机数生成逻辑不可预测。

### 2.3 硬嵌套攻击

半加密卡的最后杀手锏。有些Mifare Classic进行了改进，**随机数算法（PRNG）不再是线性的**，也就**无法预测**，就只能用这个方法破解。代价是，使用的设备更为昂贵（如Proxmark3）。

**可复制卡片的条件**：有至少一个扇区可以访问，并且是`Mifare Classic`卡片。

**原理**：

+ 这一攻击手段更加复杂，大概的思路就是：攻击者通过连续的认证请求，收集2000-4000个卡片发来的随机数挑战Nt，对这些随机数的性质进行了**逐位分析**（利用一些数学和统计规律），以尽可能地**减少原始密钥的范围**。一旦范围被缩小，就会进行暴力攻击以获取原始密钥。顺利的话，可以缩小到10^6以内。

**优点**：基本上半加密卡都可以被这样破解

**缺点**：同样需要专业设备，且可能更昂贵。破解需要花费10-20分钟。

### 2.4 暗面攻击

对于一些全加密的卡片（即每一个扇区都不知道密钥），可以先用这种方法破解一个扇区，再进行上述方法破解

**可复制卡片的条件**：全扇区都无法访问，并且是`Mifare Classic`卡片（有部分改良版不能）。

**原理**：

+ 利用 MIFARE Classic 卡片的一个特定行为：**当攻击者发送的认证密文奇偶校验位正确时，即使密钥错误，卡片仍会返回一个 4 比特的加密 NACK（否定应答）响应**。由于 NACK 明文只有 16 种可能，攻击者可以通过暴力破解获得明文，再与密文 XOR 得到 4 比特密钥流，重复收集后即可恢复完整密钥。

**优点**：半加密卡几乎都扛不住这一招。

**缺点**：你买的专业设备会更贵（如300RMB的Proxmark3），攻击一般需要花费10-20分钟。

## 3. 破解设备选择

首先，你需要知道卡片类型，**这非常重要**！

在手机上下载`Mifare Classic Tool`，并开启NFC功能，尝试读取卡的数据。如果：

+ 得到了所有扇区的数据：直接用手机就可以复制
+ 有部分扇区显示加密/不可读取，但大部分扇区是可以访问的：使用PN532或Proxmark3

**PN532** 

+ 价格：50块钱左右
+ 优点：便宜、支持上述攻击手段
+ 缺点：对高频卡，低频卡无效，无法执行更高级的攻击（如嗅探）

**Proxmark3**

+ 价格300块钱左右
+ 优点：几乎可以破解绝大多数的卡，支持多种攻击手段
+ 缺点：更贵

## 4. Encrypto-1漏洞剖析

### 4.1 LFSR算法的局限

+ **什么是LFSR？**

  **LFSR（Linear Feedback Shift Register，线性反馈移位寄存器）**。在 MIFARE Classic 中用于生成 CRYPTO1 和 PRNG 的核心组件，由一个移位寄存器和若干个抽头组成。

  在 MIFARE Classic 中存在两个这样的寄存器：一个是随机数（即挑战）生成器，另一个是keystream生成器。

  

+ **工作原理**
1. 初始值生成：

   + 对于随机数LFSR：会有一个固定的默认初始值
   + 对应keystream LFSR：通过扇区密钥进行一系列计算得到初始值

2. 迭代更新序列：

   + 每一个LFSR会各自抽取寄存器里面的固定位点的数值，并把他们进行**异或**操作后放在寄存器的最后一位，接着寄存器的每一位数值都会向前移动一位。如：

     ```
     10111000 ... 00001111
     ```

     变成

     ```
     0111000 ... 00011110
     ```

     原序列最左边的1被移除，每一个数字都往左移动一位，最右边的新数字是由固定位点的数字异或计算得到的

3. 获得数据：

   + 每一个LFSR会再次抽取不同位点上若干个值，进行一系列非线性变换来尽可能使输出值复杂



+ **局限性**：
  + 由于移位和异或本身都是线性的操作，这使得推测序列变得十分简单。相当于计算一个48元一次方程组
  + 尽管通过了非线性函数来复杂化输出，但这个函数本身复杂度不高，使用计算机可以快速破解
